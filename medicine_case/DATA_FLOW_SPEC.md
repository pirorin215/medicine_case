# データフロー仕様書

## 概要

このドキュメントは、Medicine Caseシステムにおけるマイコンとスマートフォンアプリ間のデータフローと状態管理の仕様を詳細に説明します。

## 基本設計思想

**「スマホとマイコンは常時接続されていない」**ことを前提として設計されています。

- マイコン側は極力シンプルにする
- 複雑な状態管理はスマホ側で行う
- 接続されていない間のイベントは、マイコン側で最小限の情報だけ保持する

## 1. マイコン側の状態管理

### 1.1 保持する状態

マイコン側は**1つの値のみ**を保持します：

```cpp
uint32_t g_lastIntakeTimestamp;  // 0 = 未取得（服薬していない状態）
                                 // >0 = 最後の服薬検出時のUnixタイムスタンプ
```

### 1.2 状態遷移

```
初期状態
  ↓ 服薬検出
服薬済み状態 (g_lastIntakeTimestamp = 1748762345)
  ↓ スマホから CLR:intake 受信
初期状態 (g_lastIntakeTimestamp = 0)
```

**重要**: マイコンは「いつ服薬したか（timestamp）」のみを保持し、「何回服薬したか」はカウントしません。

### 1.3 服薬検出時の処理

```cpp
void detectMedicineIntake() {
    // 1. 角度変化を検出
    if (movementAngle >= threshold) {
        // 2. 現在時刻を記録
        g_lastIntakeTimestamp = g_currentTimestamp;

        // 3. LEDフィードバック（緑点滅3秒）
        blinkGreenLED();

        // 4. BLE通知を送信試行（接続されていなければ送信されない）
        sendSensorNotification("INTAKE:%u", g_lastIntakeTimestamp);

        // 5. クールダウン開始（連続検出防止）
        startCooldown();
    }
}
```

**ポイント**:
- 通知の送信成功/失敗に関わらず、timestampは保持される
- スマホが接続されていなくても、時刻は記録される

## 2. スマホ側のデータ取得戦略

### 2.1 アクティブポーリング（能動的取得）

スマホ側が明示的に取得しに行くタイミング：

1. **BLE接続確立時**
   - 接続完了後、即座に `GET:intake` を送信
   - 見逃していた服薬イベントを取得

2. **定期的なスキャン・接続時**
   - バックグラウンドサービス（`MedicineBleScanService`）が定期的にデバイスを探索し、接続時に自動でデータを取得します。

### 2.2 パッシブ受信（受動的受信）

マイコンからの通知を受け取る：

- `INTAKE:<timestamp>` 通知を受信したら即座に処理
- 接続されている間のみ受信可能

### 2.3 取得〜クリアのフロー

```
1. スマホ: GET:intake 送信
2. マイコン: INTAKE:1748762345 応答（または NONE）
3. スマホ:
   - INTAKE受信時:
     a. ローカルDBに服薬記録を保存
     b. マイコンに CLR:intake 送信
   - NONE受信時:
     - 何もしない
4. マイコン: g_lastIntakeTimestamp = 0 にクリア
```

## 3. BLE通信プロトコル詳細

### 3.1 服薬取得コマンド

**リクエスト**（スマホ → マイコン）:
```
GET:intake
```

**レスポンス**（マイコン → スマホ）:
```
INTAKE:<timestamp>   # 未取得の服薬がある場合（timestampはUnix秒）
NONE                  # 未取得の服薬がない場合
```

### 3.2 服薬クリアコマンド

**リクエスト**（スマホ → マイコン）:
```
CLR:intake
```

**レスポンス**（マイコン → スマホ）:
```
OK: Intake cleared
```

## 4. 実装状況

### ✅ 実装済み

| 機能 | 説明 |
|------|------|
| `g_lastIntakeTimestamp` 管理 | マイコン側で最後の服薬時刻を保持 |
| `GET:intake` / `CLR:intake` | コマンドによるデータ取得とクリア |
| `INTAKE:` BLE通知 | 服薬検知時のリアルタイム通知送信 |
| 接続時オート同期 | 接続時に自動で時刻同期とデータ取得を実行 |
| バックグラウンド処理 | アプリがバックグラウンドでもServiceによりデータ取得・通知が可能 |
| 3状態履歴管理 | 服用済・未服用・対象外の履歴をDBに記録 |

## 5. 仕様の妥当性評価

### 5.1 現状仕様の評価

**✅ 良い点**:
- マイコン側は1つの変数のみを保持（シンプル）
- 接続されていない間も時刻を記録可能
- 定期的なスキャン接続により、見逃しを自動回収

**⚠️ 注意点**:
- スマホが長期間接続しない場合、次の服薬で上書きされる（1日1回以上の同期を推奨）

## 6. 推奨される運用

### 6.1 ユーザー向け

- **1日1回以上、アプリを起動（またはデバイスの近くにスマホを置く）して同期すること**を推奨。
- 定期的なバックグラウンドスキャンにより、通常は自動的に同期されます。

## 7. 用語集

- **timestamp**: Unixタイムスタンプ（1970年1月1日からの秒数）
- **ポーリング**: スマホから能動的にデータ要求を送ること
- **クリア**: マイコン側のtimestampを0にリセットすること
