# 服薬検知・判定ロジック仕様書 (Intake Detection Specification)

このドキュメントは、スマート薬ケースの傾き検知から、スマートフォンアプリ側での履歴記録までの判定ルールについて定義します。

## 1. 基本設計思想

**「マイコン側はシンプルに、複雑な判定はアプリ側で行う」**

- マイコン側はリソースが限られているため、物理的な検知と時刻の保持のみに専念します。
- アプリ側は、ユーザーが設定したスケジュールや過去の記録に基づき、その検知が「有効な服薬」であるかを高度に判断します。

## 2. マイコン側 (Firmware) の動作

- **傾き検知**: 6軸センサー（LSM6DS3TRC）を使用し、設定された角度（デフォルト70度）以上の変化を検知します。
- **時刻記録**: 検知した瞬間のUnixタイムスタンプを `g_lastIntakeTimestamp` に保存します。
- **フィードバック**: 検知と同時にLEDを緑色に点滅（3秒間）させ、ユーザーに通知します。
- **クールダウン**: ハードウェアレベルでのチャタリングや連続検知を防ぐため、検知後一定時間（デフォルト30秒）は再検知を停止します。

## 3. アプリ側 (Android) の判定ロジック

マイコンから服薬イベント（`INTAKE`）を受信した際、以下の判定を行い、有効な服薬として記録するか判定します。

### 3.1 時間帯（スロット）の判定
受信した時刻に基づき、以下の優先順位で「朝・昼・夜」のどのスロットに記録するかを決定します。

1.  **スケジュール枠内判定**:
    現在時刻がいずれかの有効なスケジュール範囲（例: 昼 12:00〜17:00）内であれば、そのスロットの記録として扱います。
2.  **通知後の猶予期間判定**:
    いずれのスケジュール枠外であっても、直近の通知から一定時間内（リマインダー間隔の2倍）であれば、直前のスロットの記録として扱います。
    *   例: 夜の枠が22:00に終了し、22:15に服用した場合でも「夜の服用」として記録。

### 3.2 スロットの状態更新条件
以下のすべてを満たす場合のみ、データベースの該当スロットを「服用済」に更新します。
- 判定されたスロットが**アプリ設定で有効**になっている。
- 判定されたスロットが**まだ「服用済」になっていない**（一度服用したら、その枠の時間は上書きしない）。


## 4. 履歴の3状態管理

`MedicineIntakeRecord` エンティティには、服用フラグとともに「その時の有効フラグ」も保存されます。これにより、履歴画面では以下の3状態が正確に表示されます。

| 状態 | 表示 | 条件 |
|:---|:---:|:---|
| **服用済** | ✅ | 判定をパスし、記録された状態。 |
| **未服用** | ⬜ | スロットは有効だが、まだ検知されていない状態。 |
| **対象外** | ー | 記録時の設定でそのスロットがオフだった状態。 |

## 5. 特殊な挙動

- **スケジュール変更時の同期**: スケジュールの時間帯や有効/無効設定が変更された場合、整合性を保つために「当日分」の記録のみがリセットされ、新しい設定に基づいた未服用/対象外状態に更新されます。
